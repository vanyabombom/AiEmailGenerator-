## 1. Резюме проекта

MailCraft AI — это готовый к продакшену MVP, созданный для устранения страха чистого листа и автоматизации деловой переписки. Используя **Next.js 14 App Router Edge Runtime**, **Vercel AI SDK** и модели **Google Gemini 1.5/2.0 / 3.6 Flash**, платформа обеспечивает время до первого токена (TTFT) менее 200 мс при потоковой генерации персонализированных писем.

---

## 2. Техническая архитектура и иерархия компонентов

### Основные архитектурные слои:
1. **Слой представления (Presentation Layer)**: Next.js App Router с серверными и клиентскими компонентами, стилизованными с помощью Tailwind CSS и микро-взаимодействий Framer Motion.
2. **Управление состоянием (State Management)**: `AuthContext` для управления сессионными токенами, тарифными метриками пользователя (Free/Pro/Enterprise), счетчиками квоты и фоллбэком на локальное хранилище.
3. **Движок генерации ИИ (`/api/generate`)**:
   - **Потоковый режим (Streaming Mode)**: Подключается к `@ai-sdk/google` (`gemini-3.6-flash`), возвращая чанковые ответы `ReadableStream`.
   - **Модуль отказоустойчивости (Resilience Engine)**: Определяет отсутствие или недействительность API-ключей и автоматически активирует автономный тестовый генератор (`lib/ai/mock-stream.ts`) с заданной ритмикой печати.
4. **Хранение данных (Data Persistence)**: Клиент Supabase Auth (`@supabase/ssr`) с фоллбэком на локальное хранилище для истории черновиков.

## 7. Отчет об инструментах разработки, ИИ-моделях и решении технических проблем

### 7.1 Использованные ИИ-инструменты и инфраструктура

- **Antigravity AI Agent Framework** (by Google DeepMind team):
  Автономный агентный фреймворк, обеспечивающий планирование, многофайловый рефакторинг, автоматическое генерацию UI и выполнение комплексных сценариев проверки.

- **Модели машинного обучения (LLM Engines)**:
  - **Claude 4.6 Opus**: Использовалась для проектирования архитектуры системного уровня, глубокой отладки Next.js App Router, работы с Supabase Auth и настройки промпт-инжиниринга.
  - **Google Gemini 3.6 Flash**: Основные потоковые модели для работы с `@ai-sdk/google`.
  - **Groq LLaMA 3.3 70B Versatile & ALLaM 2 7B**: Сверхскоростные модели вывода (500+ токенов/сек) для генерации деловой переписки.

- **MCP (Model Context Protocol)**:
  - `chrome-devtools-mcp`: Инструмент взаимодействия с разработческой консолью браузера Chrome, получения снимков дерева доступности (accessibility tree), отладки сетевых запросов и сквозной проверки пользовательского интерфейса.

### 7.2 Выявленные проблемы и их инженерные решения

1. **Ограничения API-ключей Google Gemini и выбор резервного провайдера**:
   - *Проблема*: Запросы к API-ключам Google AI Studio в некоторых регионах блокировались или вызывали ошибки авторизации 401/403.
   - *Решение*: Архитектура `/api/generate/route.ts` была дополнена прямым провайдером на базе **Groq SDK**, обеспечивающим бесшовный вызов моделей LLaMA и ALLaM при недоступности ключей Gemini.

2. **Проблема невидимого сбоя заглушки (Silent Fallback Issue)**:
   - *Проблема*: В первичной версии при любой ошибке API сервер тихо переключался на тестовый `mock-stream.ts`, скрывая истинную причину сбоя (невалидный API ключ, превышение квоты).
   - *Решение*: Введена модель *Fail-Fast*. Режим заглушки включается только при прямом отсутствии ключей в окружении, а ошибки API транслируются клиенту с понятным текстом в toast-уведомлениях.

3. **Предотвращение обрыва текста на полуслове (Token Truncation)**:
   - *Проблема*: Использование параметров `max_tokens` приводит к жесткой отрезке писем прямо на середине предложения.
   - *Решение*: Жесткие токены удалены из вызова SDK. Управление размером письма передано в **System Prompt**, который инструктирует модель умещать мысль в рамки заданного объема и всегда завершать письмо стандартной вежливой подписью.

4. **Динамическое согласование моделей Groq**:
   - *Проблема*: Случайное переключение на audio/whisper модели или ошибки `404 model_not_found` из-за изменения названий в Groq API.
   - *Решение*: Реализован динамический авто-опрос `groq.models.list()` с принудительной фильтрацией нетекстовых моделей и фиксацией фоллбэк-цепочки (`allam-2-7b` ➔ `llama-3.3-70b-versatile`).

5. **Особенности регистрационной сессии Supabase в продуктивной среде**:
   - *Проблема*: Невозможность входа в созданный аккаунт из-за включенного по умолчанию `Confirm Email` в Supabase Auth.
   - *Решение*: В `auth-context.tsx` добавлена обработка ошибок неактивированного email с четким объяснением пользователю, а для демо-режима реализовано долгосрочное сохранение аккаунтов в `localStorage`.
